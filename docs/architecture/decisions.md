# 架构决策记录（M0）

状态含义：`Accepted` 为后续实现必须遵守的决定；变更必须新增 ADR，禁止静默覆盖。

## ADR-001：模块化单体

- 状态：Accepted
- 决定：NestJS + Fastify 模块化单体，Worker 单独进程，共享领域包。
- 原因：单校 MVP 无需承担微服务的分布式事务和运维成本；模块边界为未来拆分保留路径。

## ADR-002：PostgreSQL 为事实源

- 状态：Accepted
- 决定：组队容量、确认、付款、退款和解锁仅以 PostgreSQL 提交结果为准；Redis 不作为事实源。
- 原因：核心流程需要事务、一致性约束、审计和可恢复性。

## ADR-003：按账号收费

- 状态：Accepted
- 决定：每个成团轮次中的有效账号收费 99 分，与其填写 1—3 个座位无关。
- 约束：成团至少两个不同认证账号；不能通过一个账号填写两座自行成团。

## ADR-004：成员集合变化使本轮失效

- 状态：Accepted
- 决定：进入确认后的成员增减都会使 FormationRound 失效。付款超时者被移除，本轮所有已付款订单退款；剩余成员若仍满足条件，必须重新确认和付款。
- 原因：付款和联系方式共享同意均针对明确成员集合，不能在用户不知情时替换对象。

## ADR-005：服务交付点

- 状态：Accepted
- 决定：全员确认、全员支付、全员有效共享同意且系统成功写入 ContactUnlock 后，信息服务完成。
- 约束：实际乘车不是平台服务状态；正常解锁后用户自行取消默认不自动退款。

## ADR-006：固定路线目录

- 状态：Accepted
- 决定：地点、方向和时间窗均由运营后台配置；首版不允许自由地点或持续定位。
- 原因：提升匹配密度并减少行踪数据、内容治理和输入歧义。

## ADR-007：人工学生认证与短期材料

- 状态：Accepted
- 决定：首版人工审核脱敏学生证/校园卡；保存学号 HMAC 摘要和后四位，审核决定后 24 小时删除原图，异常最长 7 天。
- 约束：不保存身份证、生日或完整学号；删除任务需要可验证审计。

## ADR-008：联系方式与同性偏好

- 状态：Accepted
- 决定：微信号是首版必填联系方式；自报性别只用于 `ANY` 或 `SAME_GENDER_ONLY` 匹配。
- 约束：未声明性别的用户不能进入仅同性组；大厅不公开性别和微信号。

## ADR-009：支付适配器顺序

- 状态：Accepted
- 决定：先以 MockPaymentGateway 完成所有成功、失败、乱序和重复回调验证，再接 WechatPayGateway。
- 约束：外部支付结果只能通过验签回调或服务端主动查询确认。

## ADR-010：里程碑验证门禁

- 状态：Accepted
- 决定：M0—M7 每个里程碑均生成验证报告并暂停；未达到门槛不得开始下一阶段。
- 原因：使架构、状态机、权限和支付缺陷在影响面扩大前暴露。

## ADR-011：独立 M0 复核后的补偿态与授权撤回

- 状态：Accepted；补充 ADR-004、ADR-005、ADR-007 和 ADR-010。
- 背景：独立复核发现退款期间的组状态、联系方式授权/读取审计、认证待上传状态和管理员材料访问无法由原契约完整表达。
- 决定：付款轮次需要退款时，Group 必须进入不可加入的 `REFUNDING`；退款重试耗尽进入 `REFUND_RETRY`。全部退款成功后才移除本轮应移除成员，并在同一事务重算为 `READY` 或 `RECRUITING`。
- 决定：成团轮次锁定成员快照和联系方式共享政策版本。`ACCEPT` 必须提交与本轮一致的结构化同意；`ContactUnlock` 表示交付资格，`ContactAccessLog` 追加记录每一次实际读取。
- 决定：解锁前撤回同意会使本轮进入退款补偿且不交付；付款后、解锁前撤回同样全轮退款。解锁后撤回立即阻止该用户发起或成为目标的后续读取，但已展示的明文无法技术性收回，政策和页面必须明确提示。
- 决定：学生认证显式使用 `AWAITING_UPLOAD`；只有对象校验通过后才进入 `PENDING`。需补交材料使用 `REQUIRE_RESUBMISSION`，旧对象立即失效并进入删除流程。
- 决定：管理员材料读取只能通过经 TOTP 再认证签发的短时、单次、对象绑定凭证；所有管理员操作声明最小角色和校区作用域。
- 约束：原 M0 PASS 被独立复核推翻；本次修复必须生成新的文件摘要和验证证据，不得把历史报告静默当作当前结论。

## ADR-012：认证状态无损表达与材料平台代理消费

- 状态：Accepted；收紧 ADR-007、ADR-010 和 ADR-011。
- 背景：第二次独立复核发现 `EXPIRED` 同时承担上传凭证过期与认证资格到期，补交会迫使实现清空历史时间；材料访问凭证也只有签发契约，没有可执行的单次消费入口。
- 决定：将首次上传过期固定为 `UPLOAD_EXPIRED`，将已审核资格到期固定为 `VERIFICATION_EXPIRED`；补交显式经过 `RESUBMISSION_AWAITING_UPLOAD` 与 `RESUBMISSION_PENDING`。`submittedAt` 保存首次成功提交时间，`latestSubmittedAt` 保存最近一次成功提交时间，`reviewedAt` 不因补交而清空。
- 决定：认证状态与三个时间字段的合法组合由 PostgreSQL CHECK 强制；OpenAPI 使用互斥 `oneOf` 分支表示首次待上传、上传过期、首次待审、已审核、补交待上传和补交待审。
- 决定：管理员材料凭证最长60秒并绑定管理员会话、校区、申请和对象。凭证原文只通过专用请求头交给平台代理端点；数据库条件更新原子消费并在同一事务追加审计，平台代理材料且不返回或重定向到 COS URL。流式读取失败仍消耗凭证。
- 决定：联系方式读取采用整组全有或全无语义。任一锁定成员撤回后整次读取失败；成功访问日志保存政策版本、被披露账号集合有序摘要和数量，不保存微信号或账号列表。
- 约束：联系方式政策迁移按 `(type, version)` 解析实际主键；同版本同摘要可复用不同 UUID，同版本不同摘要必须安全失败并要求人工决策。

## ADR-013：M1 最终态迁移候选与重置审批

- 状态：Accepted；Cedric 已于 2026-07-31 签署环境清单，原生 PostgreSQL 16.8、Redis 7.4.2、
  依赖审计和受保护 CI 门禁均已通过。
- 机器审计标记：`ADR-013_ACCEPTED`。
- 背景：独立复核发现既有 M1 迁移曾被原地扩充，随后拼接出的单文件又包含 `ALTER TYPE` 等历史步骤，不能在原生验收前称为冻结基线。当前工作区与本机未发现持久数据库，但这不能证明外部开发、测试、CI、云账号、其他开发者或备份中没有旧库。
- 候选方案：使用 Prisma 6.19.2 的 from-empty diff 直接生成最终枚举和表结构，只追加 Prisma Schema 无法表达的复合租户外键、CHECK、部分索引、触发器、函数和固定政策种子。候选目录为 `20260715000000_m1_final_state_candidate`，不包含枚举重命名、增值、加列或数据回填。
- 审批条件：项目/发布负责人必须逐项确认环境所有者、检查方式、结果、数据保留义务和停止部署联系人，并明确批准删除全部旧 M1 临时库。未知环境不能按“无数据库”处理。
- 冻结结果：PostgreSQL 16.8 上首次 `prisma migrate deploy`、第二次无待执行项、`prisma migrate status`、
  关键对象清单与并发门禁已经通过；`migration-release-baseline.sha256` 是不可变发布摘要，
  `migration-candidate.sha256` 仅保留候选阶段审计记录。
- 约束：发现任何已执行退役迁移的持久库时，重置路线自动失效，必须停止部署并设计显式前向收敛迁移。

## ADR-014：认证均为有限期且在授权时同步判定

- 状态：Accepted；补充 ADR-007、ADR-012。
- 决定：不支持永久认证。审核通过时由版本化校区认证政策计算 `expiresAt`，不得由客户端或管理员任意提交；`VERIFIED` 与 `VERIFICATION_EXPIRED` 的 `expiresAt` 必须非空且晚于 `reviewedAt`，其他认证状态必须为空。
- 决定：发布、加入、确认和付款在同一数据库事务中检查 `status = VERIFIED AND expiresAt > transactionNow`。在 `expiresAt` 的精确边界即视为失效，异步状态更新延迟不能扩大权限窗口。
- 决定：过期任务以固定 cutoff 条件更新 `VERIFIED -> VERIFICATION_EXPIRED`，重复或乱序执行保持幂等，任何任务都不能把终态恢复为 `VERIFIED`。
- 约束：认证有效期长度和政策版本在 M2 配置中确定；在此之前不得生成接受空 `expiresAt` 的稳定 DTO 或授权代码。
