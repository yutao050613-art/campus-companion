# M2 身份与学生认证安全设计

## 信任边界

1. 小程序只持有短期访问令牌和可轮换刷新令牌；数据库只保存刷新令牌摘要。
2. 模拟微信 code 由测试签名密钥签发，只能在 development/test 启用，且每个 code 只消费一次。
3. 企业微信身份截图和学生卡原图不进入 PostgreSQL。申请至少包含一种材料，可同时包含两种；API 只保存材料类型、私有对象键、内容摘要、大小和生命周期字段，普通接口不返回对象键。
4. 管理端使用独立的 `__Host-admin_session` HttpOnly Cookie。状态请求还需可信 Origin、同站 Fetch Metadata、短期 CSRF、角色和校区权限。
5. 审核员查看材料必须再次通过 TOTP。数据库签发最长 60 秒的一次性凭证，并把凭证绑定到管理员、会话、校区、申请、材料类型和确切材料行/对象摘要。
6. Worker 先原子抢占到期材料，再删除对象，最后以抢占时间和对象键 compare-and-set 标记数据库；删除失败释放抢占以便重试，补交材料通过 Outbox 精确删除已被替换的旧对象。
7. 上传 URL 使用 AES-256-GCM 不透明令牌，客户端无法从令牌解码私有对象键。材料提交后 `deleteAfter` 为空，待审核期间不进入删除队列；审核决定原子写入 24 小时删除期限。

## 主要攻击与处置

| 攻击 | 防护与验证 |
|---|---|
| 重放微信 code | 数据库唯一证据；并发只允许一个会话 |
| 盗用/重放刷新令牌 | 每次 compare-and-swap 轮换；旧令牌重放撤销整个会话 family |
| 猜测学号或批量枚举 | 学号只保存带秘密的 HMAC 和后四位；冲突返回通用 409 |
| 伪造图片 Content-Type | 上传服务同时校验签名字节、类型、大小和 SHA-256 |
| 管理员 Cookie 被跨站利用 | SameSite=Strict、可信 Origin、Fetch Metadata、CSRF 有效期和 30 秒轮换窗口 |
| 越权查看其他校区 | RBAC 与 AdminCampusScope 双重检查；失败不暴露资源存在性 |
| 一次性凭证重放 | PostgreSQL 条件更新和不可逆 usedAt 触发器；第二次统一 404 |
| 凭证签发后用户补交新材料 | 独立绑定证据保存签发时对象摘要；对象变化后凭证消费失败且绝不代理新对象 |
| 删除与提交/补交并发 | Worker 删除前以记录 ID、对象键和到期条件原子抢占；提交仅接受未被抢占的材料，不能误删或误标新对象 |
| 日志泄漏 | 结构化日志对密码、TOTP、CSRF、会话令牌、学号、对象键和材料凭证递归脱敏 |

## 密钥与生产边界

- 本地开发可使用进程临时密钥；staging/production 缺少明确密钥时启动失败。
- 生产密钥应进入腾讯云 KMS 或受控密钥注入，不进入仓库、聊天、构建产物或日志。
- M2 只实现本地私有对象存储适配器以验证状态机。生产 COS 适配、真实微信登录和域名/备案属于后续上线门禁，不得用 M2 模拟适配器直接上线。
