## 涉及不变量

- 租户所属记录显式保存 `campusId`，复合外键禁止跨校区父子关联。
- 出行需求和成员座位为 1—3；活动成员总座位由数据库触发器限制为最多 4。
- 服务订单金额固定为整数 99 分、币种 CNY；客户端不作为可信价格源。
- 联系方式查看者不能是本人；用户不能拉黑自己。
- 退款补偿使用不可加入的 `REFUNDING`/`REFUND_RETRY`；轮次锁定联系方式政策版本。
- `ContactUnlock` 与逐次追加的 `ContactAccessLog` 分离；成功日志锁定政策版本及披露集合摘要，任一撤回后整组拒绝。
- 认证区分首次上传过期、补交待上传/待审和资格到期；所有通过认证均有非空有效期，授权在精确到期边界同步拒绝。
- 管理员会话、CSRF 与最长60秒材料访问凭证均有独立持久化模型；凭证绑定签发会话并通过数据库函数原子消费。
- 幂等记录必须恰有一个用户或管理员主体；响应密文与密钥版本同时存在或同时为空。
- 数据模型不包含司机、车辆、运价、运输订单或运输状态。

## 人工对抗性复审

第二轮按攻击者视角重新阅读了入口、日志、数据库和 CI，发现并修复：

1. 从属表缺少显式校区键，可能依赖应用过滤造成跨校区关联；已加校区键和复合外键。
2. 仅有行级座位校验仍可能并发超卖；已用父组行锁与触发器增加数据库最终防线。
3. API 接受客户端请求编号可能污染链路；已忽略来路编号并生成服务端 UUID。
4. 未知异常可能泄漏内部消息；统一转换为安全 500 响应，原异常仅进入脱敏结构化日志。
5. 测试依赖共享包旧构建产物；测试命令现在先重新构建共享包，干净环境可复现。
6. Worker 队列名重复包含前缀；已改为固定逻辑队列名，由 BullMQ `prefix` 隔离。
7. Prisma 验证依赖本地环境变量；验证包装器只注入不可连接的非秘密占位 DSN，迁移仍要求显式 DSN。
8. M0 检查在 PowerShell 5 上可能误递归 `node_modules`；已限制为文档目录和单个 README。
9. 独立复核发现退款补偿态不闭合；新增 Group 退款态、唯一状态映射和数据库枚举迁移。
10. 解锁资格与每次读取审计混用；新增 ContactAccessLog、结构化政策版本同意和撤回契约。
11. 认证创建后无可表达状态；以迁移将 DRAFT 明确升级为 AWAITING_UPLOAD，并增加补交状态。
12. 管理员材料访问缺少可执行契约；新增独立会话、CSRF 轮换、角色/校区元数据和单次凭证模型。
13. 上传过期与认证资格到期共用 EXPIRED；拆为 UPLOAD_EXPIRED/VERIFICATION_EXPIRED，并增加补交状态与 latestSubmittedAt。
14. 材料 Grant 无消费路由且可在60秒内重放；新增专用请求头、平台代理端点、数据库条件更新函数和 usedAt 不可变触发器。
15. 联系方式政策回填硬编码 UUID；改为按类型/版本/摘要解析实际主键，相同摘要复用、不同摘要安全失败。
16. 数据库允许认证状态与时间矛盾；新增状态—时间 CHECK 和双引擎负向测试。
17. 联系方式读取无法证明披露范围；采用整组全有或全无，并记录政策版本、披露集合摘要与数量。
18. 预发布迁移被原地改写，且首次整改把历史升级步骤拼入单文件并过早冻结；现已从最终 `schema.prisma` 直接生成空库候选，只追加 Prisma 无法表达的约束、索引、触发器、函数和政策种子，不含 `ALTER TYPE`、`ADD COLUMN`、数据回填或前序迁移假设。该候选尚未冻结。

## 残余风险与非目标

- **阻断项**：原生 PostgreSQL 16 空库首次/二次迁移、迁移状态、对象清单、20 轮并发和原生 Redis 7 队列测试尚未执行。
- **阻断项**：共享开发、测试/预发布、CI、云账号、其他开发者和备份环境仍为 `UNKNOWN`；项目/发布负责人尚未签署重置范围。不得删除旧库或冻结候选。
- 如果发现任何已执行旧迁移的持久数据库，重置方案自动失效，必须停止部署并另做前向收敛。
- GitHub Actions 的四个第三方 Action 已锁定到经 GitHub 官方 API 核对的完整提交 SHA，checkout 不保留仓库凭据；Dependabot 已配置为每周提出 Action 更新审查。
- CI 已配置逐步保存安装、两次迁移、迁移状态、全量门禁、原生 PostgreSQL/Redis 和在线审计日志；原生测试 JSON 只要出现跳过、待定或失败即阻断，并在成功或失败时都生成 raw-byte SHA-256 清单和保留30天的产物。该工作流尚未在受保护远程仓库实际运行，不能作为已取得证据。
- 当前工作区不是 Git 仓库，当前机器也没有 Git 客户端；尚无远程仓库、提交 SHA、分支保护或 CI 运行链接。
- PGlite 能验证 PostgreSQL SQL、约束、触发器和回滚，但不能替代生产相同主版本的原生容器证据。
- M1 没有业务鉴权、支付或联系方式解锁代码，因此相关权限矩阵和故障注入留待对应里程碑。
- M0 已获独立技术 PASS，但仍等待用户显式重新确认；这与 M1 原生依赖门禁并列阻止 M2。
