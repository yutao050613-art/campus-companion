# 里程碑验证标准

## 1. 原则

验证不是“多运行几次成功路径”，而是用互相独立的方法反复挑战同一结论：规则证明、自动测试、真实依赖集成、攻击者视角审查和全新环境复现。任何阻断项失败，里程碑状态保持 `FAILED`，不得开始下一里程碑。

## 2. 每个功能的固定验证循环

1. **规则预审**：列出涉及的 `INV-*`、状态转换、权限主体、敏感数据和失败补偿。
2. **单元与属性测试**：覆盖合法/非法转换、边界值、随机事件序列；核心状态机分支覆盖率 ≥90%。
3. **真实依赖集成**：使用真实 PostgreSQL/Redis 容器验证事务、锁、回滚、队列和迁移。
4. **契约检查**：OpenAPI 与 DTO、响应和错误码一致；请求增加未知字段应被拒绝。
5. **安全负向测试**：未登录、未认证、非成员、跨校区、过期、重放、乱序、伪造和超限请求。
6. **静态门禁**：TypeScript strict、Lint、SAST、依赖漏洞、许可证、密钥、禁止词和日志泄漏扫描。
7. **对抗性复审**：完成实现后重新阅读完整差异，逐项对照威胁模型，不以原实现假设为前提。
8. **干净环境 E2E**：从空数据库迁移和种子数据开始执行主闭环及故障闭环。
9. **重复稳定性**：容量并发、支付乱序、Outbox 重投等关键测试至少重复20轮；不得隐藏 flaky test。
10. **报告与暂停**：记录命令、版本、通过/失败、覆盖率、残余风险和证据摘要，等待用户确认。

## 3. 代码质量门槛

| 类别 | 阻断标准 |
|---|---|
| 类型 | TypeScript strict 无错误；禁止无理由 `any` 和非空断言 |
| 单元测试 | Domain 分支 ≥90%；核心 API 分支 ≥80% |
| 安全 | P0/P1 为0；严重依赖漏洞为0；高危需有明确修复或不上线 |
| 并发 | 20轮并发测试均无第5座、重复订单、重复退款 |
| 权限 | 资源归属、校区范围、管理员角色矩阵负向用例全部通过 |
| 隐私 | 日志 Canary 扫描无 token、微信号、学号、材料 URL、密钥 |
| 迁移 | 候选先通过负责人审批和原生空库门禁，再冻结不可变摘要；已发布版本只允许追加前向修复 |
| 契约 | OpenAPI 可解析、引用有效、operationId 唯一、无未声明成功响应 |
| 可恢复性 | 外部失败不丢业务事实；Outbox 可重放；退款失败可安全重试 |

## 4. 强制测试场景

### 组队

- 两个账号各1座进入 READY；一个账号2座不能自行进入 READY。
- 1+3、2+2 座可以成团；第5座在并发场景稳定拒绝。
- 同一用户加入重叠时间组被拒绝。
- 同性偏好与未知/不同性别组合被拒绝。
- 确认后成员变化使旧轮次、确认和同意全部失效。

### 支付和解锁

- 客户端传金额、状态或伪造支付结果被拒绝。
- 部分付款、支付中、退款中、旧轮次和风控冻结均不能解锁。
- 重复/乱序支付回调不重复入账或回退状态。
- 未付款者超时后移除，旧轮次全额退款，剩余成员重新确认。
- `REFUNDING`/`REFUND_RETRY` 中加入、离开、新轮、下单、解锁和读取均被拒绝；乱序退款回调不能恢复招募。
- 缺少/错配联系方式共享政策版本的 ACCEPT 被拒绝；成员快照或政策版本变化使旧同意失效。
- 连续读取两次产生两条 ContactAccessLog；成功日志含锁定政策版本、规范化被披露账号集合摘要和1—3的数量，撤回后整组读取被拒绝且不返回部分联系人或记录微信号明文。
- 非成员、旧成员、跨校区管理员均不能读取微信号。

### 认证和后台

- 重复学号摘要、过期认证、已限制账号不能发布或加入。
- 创建认证后返回 `AWAITING_UPLOAD` 且三个时间字段为空；首次上传过期返回 `UPLOAD_EXPIRED` 且 submittedAt 仍为空；对象校验失败不得进入 PENDING。
- 补交必须经过 `RESUBMISSION_AWAITING_UPLOAD`/`RESUBMISSION_PENDING`，保留原 submittedAt/reviewedAt 并只推进 latestSubmittedAt；资格到期只使用 `VERIFICATION_EXPIRED`。每个状态只匹配 OpenAPI oneOf 的一个分支。
- 不允许永久认证；`VERIFIED`/`VERIFICATION_EXPIRED` 的 `expiresAt` 必须非空且晚于 `reviewedAt`，其他状态必须为空。授权覆盖到期前、精确边界、到期后、空值/非法值以及过期任务重复和乱序执行。
- M1 候选指纹不等于冻结批准；只有负责人环境清点和 PostgreSQL 16 deploy/status 通过后才生成不可变摘要。已发布迁移任何字节变化都必须阻断。
- PostgreSQL 与兼容测试引擎均拒绝 PENDING 无提交时间、AWAITING_UPLOAD 有提交时间等非法状态组合。
- 认证材料到期后对象和 API 都不可读，删除事件有审计。
- 后台无 TOTP、无 CSRF、角色不足、校区不符均被拒绝。
- 管理员材料访问凭证最长60秒，绑定对象/管理员/签发会话/校区；只允许通过平台代理端点和专用请求头原子消费。同一凭证并发兑换两次只能一次成功；过期、已用、错会话、错校区和已删除对象统一拒绝。
- 材料代理不重定向、不返回COS URL、不缓存；流式读取失败不恢复凭证。Grant原文、专用请求头、对象键和下游URL均通过日志Canary扫描。
- 管理员查看材料和审批退款产生不可修改审计记录。

### 契约与幂等

- 每个客户端业务写 operation 均声明 `Idempotency-Key`；同键同摘要重放原结果，同键不同摘要返回 409。
- 登录 code 只能消费一次；并发刷新只成功一次；重复登出安全收敛。
- 微信回调按通知 ID、平台事务号、商户订单号和密文摘要幂等，不接受客户端业务幂等键。
- 所有受保护 operation 声明 401；归属失败统一防枚举 404，角色/校区/CSRF/再认证失败为 403，状态冲突为 409。
- ErrorResponse.details 只允许白名单字段；token、微信号、对象键、URL、回调原文和异常堆栈 Canary 均不得出现在响应。

## 5. 验证报告模板

每个 `milestone-*.md` 包含：

```text
状态：PASS / FAIL / BLOCKED
范围与提交基线：
验证环境与版本：
涉及不变量：
执行的自动检查：
安全负向测试：
重复/并发结果：
覆盖率：
人工对抗性复审：
发现及修复：
残余风险与非目标：
进入下一里程碑条件：
```

报告不得声称未执行的检查已通过。因 M0 没有业务代码，覆盖率、数据库并发和 E2E 必须明确标记为“不适用，等待对应里程碑”，不能写成通过。

## 6. 证据摘要规则

- 基线清单、迁移指纹和附件留档默认使用 `SHA-256(raw-bytes)`：对指定文件的原始字节直接计算 SHA-256，不转换编码、不规范化换行，也不增加或删除末尾换行。
- 摘要记录必须同时写明证据名称或来源、摘要算法、摘要值；能够稳定引用时还应记录相对路径或附件标识。
- 文本规范化摘要只能作为跨平台内容比较的辅助证据，必须单独标为 `SHA-256(normalized-text)`，并完整注明字符编码、LF/CRLF 规则、Unicode 规范化方式和末尾换行规则。
- 不得把规范化内容摘要称为“文件 SHA-256”或用它替换原始字节摘要；同一内容的不同字节副本应分别记录。
- 外部复核报告引用的既有文件一经固定，不为修饰摘要说明而原地改写；后续澄清使用新的追加报告，并保留原文件摘要。
