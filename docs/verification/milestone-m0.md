## 对抗性复审发现及修复

### M0-F01：PowerShell 中文脚本编码失败

- 发现：Windows PowerShell 5 将无 BOM UTF-8 脚本中的中文常量错误解码，首次验证无法解析。
- 修复：验证脚本改为纯 ASCII；文档仍使用 UTF-8，并单独检查 U+FFFD 替换字符。
- 结果：在 PowerShell 5 环境重复运行通过。

### M0-F02：认证流程缺少上传提交动作

- 发现：初版契约创建了私有上传 URL，但没有在上传后触发对象校验并进入审核队列的接口。
- 修复：增加 `POST /verifications/{verificationId}/submit`；服务端必须对自己生成的对象键执行 HEAD、大小、类型和摘要检查。
- 结果：认证流程现在区分“创建上传”和“提交审核”，避免仅获取 URL 就被视为已提交。

### M0-F03：联系方式缺少安全写入入口

- 发现：初版只定义解锁读取，没有定义用户如何设置加密微信号。
- 修复：增加 `PUT /me/contact`；响应不回显明文，后端负责校验和加密。
- 结果：写入和读取边界明确，普通 Group Schema 仍不包含微信号。

### M0-F04：客户端可重复提交学号后四位

- 发现：初版认证请求同时接收完整学号和后四位，攻击者可提交不一致值。
- 修复：请求只接收临时完整学号；服务端计算带校区域分离的 HMAC 摘要和后四位，随后丢弃原值。
- 结果：验证脚本加入专门断言，阻止字段回归。

### M0-F05：验证断言未随安全写入接口更新

- 发现：增加微信号写入接口后，旧断言仍要求 `wechatId` 在整个契约中只出现一次。
- 修复：断言改为只允许两个位置，并额外验证普通 Group Schema 不含微信号。
- 结果：验证规则表达真实安全目标，而不是简单降低检查强度。

### M0-F06：报告链接先于报告生成

- 发现：加入 README 链接完整性检查后，因为本报告尚未生成而失败。
- 修复：生成本报告，再执行最终完整验证。
- 结果：所有本地交付链接可解析。
